# 行走的日子

日历放在 `source/journey/index.md` 开头，通过 `{% journey_calendar %}` 插入。运行 `npm run build` 时，Hexo 自动生成 `/journey/calendar.json`，无需手动维护第二份行程表。

页面可在“月视图”和“全年视图”之间切换。全年同时显示 12 个月，点击日期以弹窗卡片查看当天详情，可用关闭按钮、Esc 或点击遮罩关闭；点击月份标题可进入对应月视图。月视图在日历旁显示详情，两列排列时详情高度与左侧月历一致，较长内容在右侧独立滚动。

侧边栏另有紧凑月历，支持切换年月，点击日期在日历中部打开较小的浮层卡片，保留周围的日历可见，长行程在浮层内滚动；不遮罩正文，也不锁定页面滚动，可用关闭按钮或 Esc 返回月历。完整日历页保留原有行程弹窗。同页两个日历共用一次数据请求，但各自选择日期和视图，侧边栏操作不修改正文的链接锚点。访客地图已在侧边栏 Pug 模板中注释停用。

数据插入过程：构建脚本读取下列 Markdown 原文，解析日期、城市、交通与游记链接，生成 `public/journey/calendar.json`；`{% journey_calendar %}` 和侧边栏组件插入日历结构，浏览器读取同一份 JSON 后绘制日期及当天详情。无需将行程手工复制到页面。

- 到访内容与游记链接：`source/_posts/行程轨迹汇总.md`。
- 铁路记录的编辑来源：`source/_posts/行旅杂记.md` 的铁路记录表。日历直接读取原表，地图在单独更新时读取该表；CSV 为地图脚本自动导出的备份，无需编辑。
- 飞行日期、航班与里程：`source/_posts/行旅杂记.md` 的“飞行记录表”。

只录入有明确年月日的内容，月份、季节和模糊日期不会被放进日历。跨夜铁路在出发日显示出发、抵达日显示抵达。没有记录飞行时刻时不补造时刻。日期范围内的合并到访记录保留范围说明。

同一天按到访地点和交通衔接排列，保留高邮/扬州、永济/西安等同一行程内不同地点的区别。北京行迹和大城小事系列会自动匹配文章中的日期小标题，链接直接跳到对应段落，显示的游记标题不变。同一篇游记只在当天开头链接一次；不同游记重复记述的同一段到访合并展示。铁路中间站不作为新的到访记录。

到访、铁路、航班使用绿色圆点、橙色方点和紫色菱形区分。到访条目先显示“到访”，下一行将城市加粗，后接具体地点。日历只显示当天游记链接，不插入通用交通记录链接。

### 添加到访和航班

在 `source/_posts/行程轨迹汇总.md` 的对应年份、游记标题下增加日期和城市，示例：

```markdown
# 2026年
## [游记标题](../游记的abbrlink/)
- 11.20
  北京：景点一、景点二
```

同一天去了几个城市就依次写几行城市和地点。新的游记标题、链接和具体日期会自动识别，无需改代码；新文章请明确写“城市：地点”，不要仅写“市区”或省略城市。旧文章中的少量省略写法有兼容规则。飞行记录直接追加到 `source/_posts/行旅杂记.md` 的飞行记录表，“日期”写完整年月日，“时间”写起降时刻。之后运行 `npm run build`，或统一执行 `npm run deploy:all`。

### 添加铁路

在 `source/_posts/行旅杂记.md` 的铁路记录表末尾追加一行。列为“日期、出发地、目的地、车次、里程（km）、时间、备注”，跨夜写“次日”，未知时间和备注可以留空。格式示例：

```text
|2026.11.20|出发站|到达站|车次|里程|20:00-次日08:00|备注|
```

统一发布仍然从博客根目录运行：

```powershell
npm run deploy:all
```

`deploy:all` 保留原有两遍博客构建与发布：清理、生成、部署、运行博客统计，再清理、生成、部署，最后 Git 提交推送。日历仅在第一遍生成时构建一次，第二遍复用同一份临时结果；发布结束后删除临时缓存。`predeploy:all` 的文保数据准备步骤照常保留。

日常发布不会调用 QGIS，不会重新计算铁路线路、重画 PNG 或导出地图数据，也不会输出地图构建和校验报告。Hexo 只将现有 `Map/web` 文件复制到发布目录。铁路表新增记录或更改时刻、备注，会直接更新日历，不要求先更新地图。

需要更新铁路网页或静态地图时，再单独让大模型处理并检查线路；完整地图构建命令为 `npm run map:update`，它不会自动运行于日常发布。

新到访城市和省份也要加入行旅杂记的到访清单。新线路生成后查看路线是否符合实际；需要指定经过站时，在 `parse_source.py` 的 `ROUTE_CONTROL_POINTS` 中增加该车次和起终点的约束；尚未收录的经过站还需在 `build_routes.py` 的 `WAYPOINT_COORDS` 中补充坐标。

如果只更正已有铁路记录的日期、时刻、备注，可以用更快的方式：

```powershell
& .\Map\制图工具\update_travel_history.ps1 -TimetableOnly
```

脚本默认使用本机 `E:\QGIS 3.44.8`，安装位置变化时可传 `-QgisPython`。脚本只构建和校验，不执行博客部署或 Git 推送。

### 同一天如何排序

火车和飞机先按出发时刻排序，跨夜抵达放到次日的抵达时刻。到访根据“城市：地点”与交通的到达地、出发地匹配，放在到达后、离开前；高邮与扬州、祁阳与永州等地点分别匹配。同一篇游记内的到访先后顺序按汇总中的书写顺序保留。

到访没有时刻时，排序依赖地点和文字顺序，并不能知道你实际几点参观；同城多次往返或地点省略时应检查结果。已有明确的人工顺序修订会保留，例如神木—府谷 K8204 放在 2026 年 5 月 16 日到访之后。

数据处理位于 `lib/journey-calendar.cjs`，展示脚本与样式位于 `source/js/journey-calendar.js`、`source/css/journey-calendar.css`。运行 `node --test test/journey-calendar.test.cjs` 检查日期过滤、行程顺序、跨夜和游记去重。

两个日历共用 `lib/journey-calendar-view.cjs` 的结构模板。侧边栏入口为 `themes/butterfly/layout/includes/widget/card_journey_calendar.pug`。正文及文章列表保留卡片并加强阴影，侧边栏恢复浅边框、淡阴影卡片，块间距为 10px；每页 15 篇，桌面无封面文章卡片至少 156px 高。桌面首页将分页放在独立一行，使侧边栏的底部与最后一张文章卡片对齐。样式和侧边栏浮层位于 `source/css/site-layout.css`，由 `_config.butterfly.yml` 统一加载。
