# 国保足迹

日常编辑时直接双击 `edit.cmd`：启动器会检查并启动本地保存服务，然后自动打开编辑页；无需手动输入命令或网址。该编辑页会将每次修改自动保存到 `data/visits.private.json`。直接打开 `index.html` 仍可使用，但受浏览器安全限制，记录只能保存在该浏览器中，不能自动写入博客数据。名录页支持按省级、地级、县级行政区、批次、年代、类别和到访状态筛选，并可按省级行政区、批次或年代分组，填写到访时间与备注。页面默认显示全国已到访项目；选择具体省级和地级行政区后，可继续筛选县级行政区。

“到访统计”是 `index.html?view=stats` 独立视图，与名录页共享浏览器记录，提供年度与逐月趋势、各批完成度、类别、年代和省级行政区进度。点击年份可展开该年 12 个月；点击月份、批次、类别或年代图表可进入对应名录。名单默认每页显示 20 项，支持输入页码直达；按批次查看时使用该批公告序号排序。页面列表只展示名称，正式编号仍保留在详情、搜索和基础数据中。年代筛选按完整时代中的最早阶段归类，黄色标签仍显示公告所载的完整时代；无法判断最早阶段的记录归入“其他”，不单设“跨时期”。“青铜时代”属于考古学分期：以青铜时代为最早阶段的记录归入“夏商周”，“新石器至青铜时代”则按最早阶段归入“史前”。

公告中的“一作”异名经过规范化：仅行政前缀或单字正误差异直接合并，确有辨识价值的异名保存在 `alias` 字段并以小号括号显示。

## 数据口径

- 原始名录包含第一至第八批主体 5,058 项，以及第四至第八批公告中的 238 条合并关系。
- 页面按现行合并单位统计：合并项目不重复列出，使用公告明确的合并后名称，并归入主体最早获批的批次；原名称仍可用于搜索。
- 合并过程不在页面和公开数据中显示，只保存在本地 `merged-review.md` 与 `data/merge-relations.json`。
- 到访记录保存在当前浏览器的 `localStorage` 中，不会写回基础名单。
- “备份记录”导出 JSON，可用于防止浏览器数据丢失、迁移到其他浏览器，以及日后生成博客公开数据；“导入备份”用于恢复该 JSON。
- “导出当前 CSV”会把当前筛选结果和个人记录导出为表格，适合在 Excel 中核对或另行统计，不参与页面日常保存。
- CSV 使用 UTF-8 BOM，可直接用 Excel 打开；`period` 是归并后的年代分类。`visit_time` 接受年份、年月、完整日期或自由文本。
- 年月日推荐使用 `2024`、`2024-05`、`2024-05-18`；也支持 `/`、`.` 或“年月日”分隔。年度统计读取所有含年份的记录，月度统计只读取含月份的记录。

`province`、`city`、`district` 统一采用截至 2025 年 12 月 31 日的现行三级行政区划；`current_location` 用于页面展示：跨县列出全部区县，跨市只列地级市，跨省只列省级行政区。公告公布时的原始地名只保留在本地 `location` 字段，不在页面或公开数据中显示。东莞、中山、儋州等地级市在内部数据中标为“不设县级行政区”，页面地点只显示到地级市。

## 发布到静态博客

静态博客无法读取浏览器 `localStorage`，因此自动发布必须通过本地编辑服务维护仓库记录文件：

1. 双击 `edit.cmd`。
2. 在自动打开的页面中更新到访记录，页脚显示“已自动保存到博客数据”后即可关闭。
3. 照常运行 `npm run deploy:all`。

`npm run deploy:all` 的前置步骤会先校验国保记录；其中每一次 Hexo 生成都会通过 `after_generate` 钩子自动复制页面到 `public/heritage/`，读取私有记录并生成公开只读数据。公开数据只包含到访状态和时间，不包含个人备注；`visits.private.json` 已加入 `.gitignore`，不会被 Git 提交。博客导航中的 `Heritage` 指向 `https://kangaroogao.com/heritage/`。

原先通过双击 HTML 保存的浏览器记录不会自动迁移到本地服务。首次切换时先在原页面“备份记录”，然后在本地服务页面“导入备份”一次；此后无需再手工导出。

## 文件

- `index.html`：本地入口。
- `data/heritage.csv`：完整结构化数据，预留个人记录列。
- `data/units.js`：供本地页面直接读取的现行合并名录。
- `data/merge-relations.json`：238 条公告合并关系的本地结构化记录，不发布到博客。
- `data/location_codes.json`：用文物点位与县级边界校正旧县拆分后的现行县级代码。
- `merged-review.md`：238 条后续合并关系按现行单位和最早主体批次归类的本地记录。
- `data/runtime.js`：本地/公开只读运行模式配置；公开版本由 Hexo 自动生成。
- `data/visits.private.json`：本地服务自动维护的私有记录，不提交 Git、不复制到博客。
- `scripts/build_data.py`：重新抓取、校验并生成 CSV/JS 的脚本。
- `scripts/build_merged_review.mjs`：由完整名录折叠现行单位，并生成本地合并记录；由 `build_data.py` 自动调用。
- `scripts/editor_server.mjs`：本地编辑服务。
- `scripts/prepare_publish.mjs`：`npm run deploy:all` 前的记录校验。
- `edit.cmd`：Windows 一键启动并打开本地编辑页。
- 博客根目录 `scripts/heritage_publish.js`：Hexo 自动发布钩子。

## 数据来源

- 国务院第一至第八批公布通知，使用维基文库收录的政府公文文本；政府公文属于公有领域。
- 标准化编号与分类辅助数据来自 [china-cultural-heritage](https://github.com/lingdian1226/china-cultural-heritage)，许可证为 CC BY 4.0。
- 现行三级行政区划采用中国·国家地名信息库截至 2025 年 12 月 31 日的数据镜像；历史县级代码沿革参考 [areacodes](https://github.com/yescallop/areacodes)。
- 缺少县级地址的早期项目参考 [CulturalWhisper](https://cultural.rainywhisper.com/) 收录的国家文物局综合行政管理平台点位，并用县级行政区边界做空间校正；明确的数据错误保存在脚本的显式校正表中。
- 第八批数量同时以[国家文物局公布名单](https://www.ncha.gov.cn/art/2019/10/18/art_2289_157100.html)校验。

重新生成数据：

```powershell
python .\scripts\build_data.py
```
